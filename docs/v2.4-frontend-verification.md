# v2.4 frontend — verification

Brief: `docs/briefs/v2.4-frontend.md`. Contract: `docs/briefs/contract-v2.4.md` (merged from `feat/backend`).

## What changed

1. **Token kind.** `tokens=` goes to `get_metrics` as `tokenKind` (`outputTokens` → `output`). KPIs (cost
   and tokens named after the kind), provider lines, the daily chart in every grouping, Por modelo, Por
   proyecto and the project's branch series count only that kind. The token bar keeps every kind (a
   query without the kind, usually cached) so the kind can be switched. A note under the KPIs says
   sessions, messages, tools and active time do not depend on it.
2. **Por proyecto.** The chart draws every project (no "Resto"); the legend keeps two lines, largest first,
   plus "+N más". The panel keeps its threshold + "Ver todos".
3. **Family filter.** Sesiones' model select offers each family (`modelo=familia:opus`, "Opus (todas)").
4. **Sparkline.** The tooltip lists only active days, by date, at most 180 px tall with scroll, `fixed` so
   the table does not clip it.
5. **Proyecto = Resumen scoped.** `useDashboardData({ projectPath })` + `Dashboard` serve both pages; the
   project's metrics come from the backend with `projectPath` instead of a client-side aggregation.

## Performance (Por proyecto)

Recharts now lays out one bar per day and `DayStack` draws the stack as plain SVG. Switching to Por
proyecto, 30 days, jsdom (relative numbers; a browser is several times faster):

| Projects | Before | After |
| --- | --- | --- |
| 5 | 146 ms | 97 ms |
| 33 | 317 ms | 120 ms |
| 60 | 720 ms | 103 ms |
| 120 | 1588 ms | 162 ms |

## Checks

- `npm run check` (read-only guard, `tsc`, 204 Vitest tests, `cargo test`) and `npm run build` pass.
- New tests: `Sparkline.test.tsx`, `family-filter.test.ts`, `daily-chart.test.tsx`,
  `project-dashboard.test.tsx`, `token-kind.test.tsx`, route test for the family filter.
- Real backend: `npm run tauri dev` started and served the dashboard (`get_metrics` / `get_tool_stats`
  IPC on the real corpus). The real-corpus benchmark (`metrics_perf`, release, `--ignored`) passes:
  every filter combination × every token kind < 50 ms.
- Visual (mock, built-in browser): light and dark, 1440 and 600 px, no horizontal overflow.

## Known limits

- Resumen's model cross-filter is still one model: a family needs the metric commands to accept one
  (additive contract change, e.g. `model` accepting `familia:<f>`).
- "Archivos más tocados" on a project follows the range only, not the other cross-filters (it reads
  session details, not the metric commands).
- The real Tauri window was not driven by clicks (the automation could not focus it); the UI was
  checked with the mock, which serves the same `Metrics` shape.
