# Brief — v2.1 UI feedback after testing with real data

Branch `feat/frontend`. Read `AGENTS.md`, `docs/architecture/frontend.md`, the color rules in
`docs/mockups/README.md` and the user's color preferences below. Contract stays unchanged.

User feedback (dark theme, real data) — fix all of it:
1. **"sin precio" marker**: keep only the yellow symbol next to the cost; the explanation ("incluye N tokens
   sin precio") goes in a tooltip on hover/focus (accessible). Nothing may overflow: the per-provider line in the
   cost KPI is clipped today ("Claude US$ 2.0(") — make KPI sub-lines fit at every width (wrap or abbreviate).
2. **Neutral color for "Todos"**: with the provider filter on "Todos" (both providers), nothing provider-scoped
   may use Claude's color (e.g. the selected KPI bar, Total series in the trend). Introduce a general app color
   token (placeholder until the app accent is defined), clearly distinct from Claude and Codex, in light and dark.
   With one provider selected, keep that provider's color.
3. **Model colors follow their provider**: Opus currently renders blue. Claude model families/versions must use
   analogous shades of the Claude palette (red/amber/wine family); Codex families of the Codex palette
   (blue/cyan/violet family). Versions of a family = clearly distinct tones within the family. Validate the
   palettes (adjacent pairs, colorblind-safe) in both themes.
4. **Project colors**: today only 3–5 projects get a color and the rest are gray. Never gray for data. Assign
   colors by usage rank within the current view (not fixed per project), from a larger validated categorical
   palette; when projects outnumber distinct hues, reuse hues with different lightness. No "Otros" folding.
5. **"Auto Review" is not a model**: `codex-auto-review` is the guardian reviewer. Exclude it from model lists,
   model families, the "Por modelo" grouping/trend and session model badges. Show its usage separately as
   "Revisiones automáticas" (tokens, cost/unpriced marker) where models are listed, so totals still add up.

User color preferences (keep): provider color swappable in one place; analogous variations, not near-identical
monochrome; no gray for important data; each entity type has its own color rule.
