# Brief — v2.6 frontend: the tool filter filters everything

Branch `feat/frontend`. Read `AGENTS.md`, `docs/architecture/frontend.md` and `docs/briefs/contract-v2.6.md`.
The backend implements the contract in parallel on `feat/backend` and **owns `src/api.ts`, the mock and
`src/bindings/`: do not edit them**. Start with the parts that don't need them; `git merge feat/backend` as soon as
its `api.ts` signatures land (check `git log feat/backend`), and again when it finishes. Never touch `src-tauri/`.
Do not automate clicks on the user's desktop. Timebox measurements to ~15 min.

1. **Tool filter everywhere**: the `herramienta` filter goes to every query (`getMetrics`, `getToolStats`,
   `listSessions`, the project page, the slot/allKinds side queries and prefetch keys). Every panel then shows the
   sessions that used the tool (KPIs, daily chart in every grouping, Por proyecto/modelo/proveedor, activity heatmap,
   Sesiones list, Archivos más tocados). Tool rows become clickable filters like everything else; the chip reads
   "Herramienta: Bash". Remove the "only the tool tile" workaround and its notes.
2. **Per-day tool errors**: Herramientas in the daily chart splits ok/error per day again (Total), using
   `tool_errors`; in groupings, show the errors in the tooltip. Tool tile keeps calls/errors.
3. **Token kind in groupings**: the backend already scopes grouped series by token kind (since v2.4). Verify
   Por proveedor/modelo/proyecto under a token kind show only that kind, and remove any leftover note saying they
   count every kind (code, UI and `docs/v2.3-frontend-verification.md` "Known limits").
