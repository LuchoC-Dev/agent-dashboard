# Brief — v2.3 frontend: chart performance, correct model filter, complete cross-filtering, back navigation

Branch `feat/frontend`. Read `AGENTS.md`, `docs/architecture/frontend.md` and `docs/briefs/contract-v2.3.md`.
The backend implements the contract in parallel on `feat/backend`: build against the spec with the mock; when it
lands, `git merge feat/backend`. User feedback from real use:

1. **The daily chart is very slow.** Apply React performance best practices properly and measure (React Profiler,
   production build, real-size data): use the precomputed `series_by_*` from the backend instead of computing the
   trend from session summaries; memoize data/props so hover does not re-render the whole chart; isolate the tooltip/
   hover state; `useDeferredValue`/`startTransition` for metric/grouping switches; code-split chart-heavy components
   with `React.lazy` + `Suspense` where it helps first paint; avoid re-creating Recharts children on every render.
   Report before/after timings for: first paint of Resumen, switching metric, switching grouping (esp. Por proyecto),
   hovering segments.
2. **Model filter bug**: selecting `Sol 5.6` shows other Codex models (Terra, Luna) in the chart because it filters
   sessions, not messages. With the v2.3 series it must show only the selected model's numbers everywhere.
3. **Por proyecto grouping**: instead of a fixed top N, show every project whose share of the selected metric in the
   current view is ≥ a threshold (start at 3 %, a single constant), and fold the rest into "Resto · N proyectos".
   Same rule for the "Por proyecto" panel list.
4. **Everything selectable must filter.** Audit every clickable/hoverable/selectable element in Resumen (and the
   project/session dashboards that reuse them) and list them in your report. Each one either applies a filter or is
   clearly not interactive. Heatmap cell → weekday+hour filter (new contract filter); clicking a weekday label →
   weekday filter; clicking an hour label → hour filter. Token-kind bar, KPI provider lines, tool rows, model rows,
   project rows, legend entries: all filter. Filters show as removable chips; clicking an active one clears it.
5. **The "Por modelo" stacked bar** (top of the panel) is not clickable: make each segment hoverable (tooltip,
   highlight, animation) and clickable (model filter), like the chart.
6. **Back navigation**: there is no way to go back. Add back/forward controls in the top bar (disabled when not
   possible), plus Alt+←/Alt+→ and mouse back/forward buttons. Filters live in the URL, so going back restores them.

Read-only UI, light/dark, ≤640 px, Vitest for the filter audit, URL state, threshold grouping and navigation.
Before/after screenshots and timings in your report. Small conventional commits on `feat/frontend`. Don't merge, don't push.
