Two parsing bugs, confirmed against the owner's real logs:

1. **Claude: no session ever gets its title.** `src-tauri/src/sources/claude.rs` (`parse_events`, ~line 383) reads the
   `ai-title` entry from `title` or `content`, but Claude Code writes `{"type":"ai-title","aiTitle":"…","sessionId":…}`
   (every real entry uses `aiTitle`). Read `aiTitle` first, keep the old keys as fallbacks. If a session has several
   `ai-title` entries, keep the latest one.
2. **Codex Desktop: user messages with array content are dropped.** `user_text()` in
   `src-tauri/src/sources/codex/parser.rs` (~line 1117) handles `content` as a string, `text`, or `text_elements`, but
   Codex Desktop writes `item.content = [{"type":"text","text":"…"}]`. It returns "", so the session loses its first
   prompt (shown as "Sesión sin título" when it's not in `session_index.jsonl`) **and** the `continue` (~line 708)
   drops the user message from the conversation. Read the array form (concatenate text parts, ignore non-text parts).
   Check the rest of the Codex and Claude parsers for the same string-vs-array assumption.
