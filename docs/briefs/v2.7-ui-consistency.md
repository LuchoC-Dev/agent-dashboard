# Brief — v2.7 frontend: accent and clickable rules, consistent tables

Branch `feat/frontend`. Read `AGENTS.md` and `docs/architecture/frontend.md`. Do not touch `src-tauri/`, `src/api.ts`,
`src/bindings/` or the mock. Do not automate clicks on the user's desktop. **Stop every dev server you start before
reporting.** Timebox visual checks to ~15 min.

The owner reviewed Resumen with real data and found inconsistent styling across panels (each was built by a different
agent). Apply these **design rules everywhere**, then write them into `docs/architecture/frontend.md` as the rules for
future work:

1. **Clickable is visible at a glance.** Anything that navigates or filters shows it without hovering. Inside tables
   and data lists the cue is **typographic** (semibold weight in the normal text color, plus hover/focus underline and
   pointer), never the accent color. Non-clickable values stay regular weight. Same treatment for the same kind of
   element in every panel and page.
2. **No accent color inside tables / data areas.** The app accent (`--app-accent*`) is for **mini-CTAs** ("Ver todas
   (337) →", "Ver las sesiones detrás de estas métricas →", "Ver todas →"), selected states and focus. Provider, model
   and project swatches are data colors, not accent: keep them, but use one swatch style per dimension consistently
   (today models use dots and projects/providers squares; pick a rule and apply it everywhere).
   Status colors (errors ⊗) stay.
3. **Markers must not misalign numbers.** The `*` "sin precio público" marker (`UnpricedMark`) goes **before** the
   amount (or in a fixed-width slot) so amounts right-align in every column: Por proyecto, Por modelo, Sesiones
   recientes, Sesiones, Proyectos, session detail, subagents. Same for other inline markers next to numbers
   (e.g. `· ⊗ 3` after tool counts) — keep columns aligned.

Known offenders (Resumen): **Por proyecto** colors project names with the accent; the `*` after the cost misaligns the
amounts. **Sesiones recientes** mixes colors (accent titles, colored project names, different swatches per column).
Then audit every other table/list: Por modelo, Herramientas más usadas, Sesiones, Proyectos (+ project page),
Herramientas (ranking + matrix), session detail (panels, subagents, timeline lists) — light and dark.

Prefer fixing shared pieces (`DataTable`, `Swatch`, `UnpricedMark`, `styles.ts`) over per-panel overrides; remove
one-off styles that the shared pieces make unnecessary. Add Vitest coverage for the rules where practical (e.g. no
accent class inside table bodies, unpriced marker position, clickable cells carry the clickable style).
Before/after screenshots from `npm run dev:mock` (headless) for Resumen, Sesiones and a session detail, light and dark,
in the scratchpad (not committed).
