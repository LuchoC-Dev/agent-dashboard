# Brief — v2.2 frontend: loading, instant filters, cross-filtering, chart polish

Branch `feat/frontend`. Read `AGENTS.md`, `docs/architecture/frontend.md` and `docs/briefs/contract-v2.2.md`.
The backend agent implements that contract in parallel on `feat/backend`; build against the spec using the mock
(extend `src/api.ts` mock filtering for `projectPath`/`model` yourself if the backend hasn't landed; when it lands,
`git merge feat/backend` and resolve). User feedback from real use (dark theme):

1. **One window from the start.** Today a different first screen appears (Claude-only, without provider filter,
   different counts) and then switches to the final one. Show the final shell immediately (provider filter,
   sidebar, layout) and put each section in its own loading state (skeletons) until its data arrives; use
   `SourceScan.scanning` per provider. No layout jump when data lands.
2. **Instant filter switches.** After the first load, switching provider (Todos/Claude/Codex) or date range
   shows a ~0.5 s loading state the first time. "Todos" already contains everything: switching must not flash
   loading. Keep previous data while fetching (`placeholderData`), prefetch the other providers and ranges in the
   background after the first screen, and derive what can be derived client-side. Measure before/after.
3. **"Por proyecto" panel**: show the top N projects (like "Sesiones recientes") and a "Ver todos" link to Proyectos.
4. **"Por modelo" panel**: provider rows collapsible (expanded by default); model families collapsible (collapsed by
   default), keyboard accessible.
5. **Daily chart box keeps its size** when switching Total / Por proveedor / Por modelo / Por proyecto (legend and
   details must not grow it). Legend: at most 2 lines; overflow becomes a "+N más" control that reveals the rest
   (popover). The "Por proyecto" trend is slow: profile and fix (e.g. limit series to the top groups for the
   selected metric and aggregate the tail into one clearly labeled "Resto" segment in the chart only — never gray
   for top data — or another approach you justify with measurements).
6. **Segment hover + cross-filtering.**
   - In stacked bars, each sub-segment is individually hoverable (highlight that segment, dim the rest, smooth
     animation respecting `prefers-reduced-motion`); the tooltip shows the hovered segment first.
   - Clicking a segment applies that filter to the whole Resumen (provider, model, project or day — whatever the
     segment represents), via URL params, with a visible removable filter chip bar. The same applies to the other
     visualizations: hourly heatmap cell (day of week/hour → filter or highlight, your call, justify), token-kind bar,
     KPI provider lines, model/project rows. Clicking an already active filter clears it.
7. **Bug**: hovering/clicking one "sin precio" asterisk opens the tooltip on both asterisks; each must open only its own.

Read-only UI, light/dark, ≤640 px, Vitest coverage for filters/URL state and the tooltip bug, before/after
screenshots and timings. Small conventional commits on `feat/frontend`. Don't merge, don't push.
