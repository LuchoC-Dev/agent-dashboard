# Brief — v2.5 frontend: git projects, Codex homes, family filter, files touched

Branch `feat/frontend`. Read `AGENTS.md`, `docs/architecture/frontend.md` and `docs/briefs/contract-v2.5.md`.
The backend implements the contract in parallel on `feat/backend`; build against the spec with the mock, then
`git merge feat/backend` when it lands and verify against the real backend logs (`npm run tauri dev`).
Do not automate clicks on the user's desktop. Timebox measurements to ~15 min.

1. **Projects by `project_key`**: everywhere (Proyectos list, project page/route, Resumen panels, filters, chips,
   colors, Sesiones project column/filter) group and link by `projectKey`, label with `projectName`. The project page
   shows the repo's working copies/worktrees (distinct `projectPath`s with session counts and last activity).
   Route/URL uses the key (encoded); old path URLs redirect if possible.
2. **Both Codex homes**: the sidebar source list and scan notices show every directory read (one line each), and the
   session detail shows which home a Codex session came from (`sourceDir`).
3. **Family click-to-filter**: clicking a model family row/segment (Por modelo, chart legend, Sesiones select) filters by
   the whole family using the new `models` arg; chip reads "Familia: Opus". Single-model clicks keep `model`.
4. **"Archivos más tocados"** (project page and wherever it appears) must honor every active filter (range, provider,
   model/models, token kind if applicable, weekday/hour), not only the date range.

Vitest for each point, light/dark, ≤640 px. Small conventional commits on `feat/frontend`. Don't merge, don't push.
Report ≤ 15 lines.
