# Brief — v2.4 frontend

Branch `feat/frontend`. Read `AGENTS.md`, `docs/architecture/frontend.md` and `docs/briefs/contract-v2.4.md`.
The backend implements the contract in parallel on `feat/backend`; use the mock until it lands, then
`git merge feat/backend` and **test against the real backend** (`npm run tauri dev`) before finishing.
Timebox measurements: don't spend more than ~15 minutes on profiling.

User feedback from real use:
1. **Token-kind filter**: clicking a token kind (e.g. "Lectura de caché") today only updates the Tokens KPI. With the
   v2.4 `tokenKind` arg, every token and cost figure must follow the filter (KPIs, daily chart in every grouping,
   Por modelo, Por proyecto, provider lines). Sessions/messages/tools/active time don't depend on token kind: keep
   them and show a short note so it isn't confusing.
2. **Por proyecto (daily chart)**: the threshold/"Resto" approach was not what the user wanted. The chart must show
   **every project** as its own colored segment (no "Resto" segment in the chart). Only the legend below is limited:
   show the entries that fit in two lines (largest first) and a "+N más" control listing the rest. Keep it fast
   (measure switching to Por proyecto with all projects; if Recharts can't do it smoothly, justify an alternative).
   The "Por proyecto" panel list keeps "top + Ver todos".
3. **Sesiones: filter by family.** The model select only allows single models; family headers (Opus, Sol, …) must be
   selectable too and filter all its versions. Same for any other model filter in the app.
4. **Proyectos: sparkline tooltip** shows every day of the range and covers the screen. Show only days with activity
   (compact, max height with scroll if needed, sorted by date).
5. **Proyecto view must reuse the Resumen components.** It still has bugs already fixed in Resumen and its elements
   are not click-to-filter. Refactor so Resumen and Proyecto (and Session summary where it applies) render the same
   dashboard components with a scope (e.g. fixed project), sharing filtering, cross-filter clicks, chips, loading,
   tooltips and fixes. Remove the duplicated code. Document the pattern in `docs/architecture/frontend.md` so future
   fixes land once.

Read-only UI, light/dark, ≤640 px, Vitest for each point. Small conventional commits on `feat/frontend`.
Don't merge into `main`, don't push. Final report ≤ 20 lines.
