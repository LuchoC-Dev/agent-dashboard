# v2.2 frontend verification

Brief: `docs/briefs/v2.2-frontend.md`. Branch `feat/frontend`, built against
`docs/briefs/contract-v2.2.md` with the mock, then merged with `feat/backend` (`9b5451e`,
cross-filtered metrics and `SourceScan.scanning`). The only conflict was the mock's metric
filtering in `src/api.ts`: the backend's version (contract owner) was kept and the frontend's
duplicate helper dropped; the frontend's contract tests (`src/api-filters.test.ts`) pass on it.
Not run against the native app in this round (`npm run tauri dev`).
Screenshots are local in `.qa/v2.2/` (ignored), as in previous rounds.

## What changed

1. **One window from the start.** The shell renders final at once: provider control (a source
   still scanning counts while installed), sidebar (counts as skeletons until final) and layout.
   Resumen shows a skeleton per section until its provider scope finished scanning
   (`SourceScan.scanning`; falls back to the global flag). A provider already scanned shows its
   data while the other still scans. Mock fixture: `?estado=escaneo` (Claude ends at 0.9 s,
   Codex at 2.6 s). Skeleton heights measured equal to the final sections at 1440, 1300, 1240,
   1100, 900 and 600 px (the model table can differ by one row at 1100 px).
2. **Instant filter switches.** Session lists derived client-side; `keepPreviousData`; idle
   prefetch of every provider × range preset after the first screen.
3. **Por proyecto** lists the top 7 (as many as Sesiones recientes) with "Ver todos (N) →".
4. **Por modelo**: provider rows expanded, families collapsed, real buttons with `aria-expanded`.
5. **Daily chart** keeps its box (363 px at 1440, 401 px at ≤900 for every grouping). Legend of at
   most two lines with a "+N más" popover; the day list moved to a "Días" popover. Groupings
   draw the top 8 series by the selected metric plus one "Resto · N …" segment (`--color-rest`,
   chart only; top series keep their own colors). Empty segments draw no rectangle.
6. **Segment hover + cross-filtering.** One segment lit, the rest at 32 % opacity with a 150 ms
   transition (none under `prefers-reduced-motion`); the tooltip leads with it. Clicks filter by
   provider, model, project, token kind or day via the URL with a chip bar. Clicking the active
   value clears it. Heatmap: highlight, not filter (weekday/hour is not a metrics dimension and
   filtering by it needs per-message data the contract keeps out of payloads; a session spans
   many hours). Model filter + Total grouping reads the backend's per-day buckets, so the chart
   matches the KPI totals.
7. **"Sin precio" tooltip bug.** A KPI tile was one button holding several marks; focusing it
   (a click) opened all. Keyboard focus now opens only the first mark, a pointer focus none, and
   the provider lines are now their own buttons.

## Timings

Production mock build, Chrome, 320-session / 45-project corpus derived from the mock, 150 ms
emulated command latency (`sessionStorage["mock-latency"]`). "Loading frames": animation frames
with a skeleton or the scanning state on screen after the click.

| First switch after load | Before | After |
| --- | --- | --- |
| Todos → Codex / Claude | 241–250 ms, 8 loading frames | prefetched: ~95 ms, 0 frames |
| 7 / 30 días | 238–242 ms, 8–9 loading frames | prefetched: ~90 ms, 0 frames |
| Same under heavy machine load | 431–531 ms, 7–9 frames | 275–445 ms, 0 frames |

"Por proyecto" grouping, click until the bars stop changing, 4× CPU throttle:

| | Before | After |
| --- | --- | --- |
| Quiet machine (3 clicks) | 410–516 ms | 223–291 ms |
| Loaded machine, median of 18 (min) | 2577 ms (1111) | 1167 ms (524) |

JS self time is small; most of the cost is SVG layout and paint, so fewer series is the lever.
First paint of data is unchanged at 150 ms latency (~940 ms both) and ~90 ms slower at 0 ms
latency: the full list now waits for the scan report (its key needs the scan state).
